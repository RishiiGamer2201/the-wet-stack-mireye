# API reference

Interactive documentation is generated by FastAPI at `/docs`; the machine-readable schema is at
`/openapi.json`. All request and response bodies are Pydantic models — the frontend types in
`apps/web/src/lib/types.ts` mirror them.

Base path: `/api`

## Operational

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/health` | Liveness. `{status, version}` |
| `GET` | `/ready` | Readiness: store, Mireye, graph, vector, seeded state |
| `GET` | `/meta` | Demo-mode flag, the adapter actually in use per service, dimension weights and labels, safety disclaimer |
| `POST` | `/admin/seed` | Wipe and reseed the synthetic demo project |
| `POST` | `/admin/reset` | Clear all data |

## Projects

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/projects` | List projects |
| `POST` | `/projects` | Create a project (name, targets, weights) |
| `GET` | `/projects/{id}` | Project detail: sites, documents, changes, counts of requirements/evidence/open gaps |
| `PATCH` | `/projects/{id}` | Update targets or dimension weights (negative weights → 422) |

## Before Construction

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/projects/{id}/sites` | Candidate sites |
| `POST` | `/projects/{id}/sites` | Add a site by address (geocoded) or coordinates. Requires one or the other; coordinates are range-validated |
| `DELETE` | `/projects/{id}/sites/{site_id}` | Remove a candidate |
| `POST` | `/projects/{id}/investigations/site` | **Run the investigation.** Body: `{site_ids?, weights?}`. Returns the full `Investigation` including steps, events, ranking, decision and next actions |
| `POST` | `/projects/{id}/ranking` | **What-if on weights.** Re-scores stored evidence; returns the new ranking, the baseline and a rank-change explanation |
| `POST` | `/projects/{id}/sites/{site_id}/override` | **What-if on a value.** Records `user_confirmed` evidence (superseding the old record) and re-ranks |

## During Construction

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/projects/{id}/changes` | Equipment change cases |
| `GET` | `/projects/{id}/changes/{change_id}` | Change detail: both equipment configurations, linked site, requirements, assumptions, latest investigation id |
| `POST` | `/projects/{id}/changes/{change_id}/analyze` | **Run the analysis.** Verification gates → deltas → stale assumptions → impacts → decision → next action |
| `GET` | `/impact/{change_id}?max_depth=5` | Traverse `Change → Stale assumption → Discipline → Activity → Commissioning`. 404 until the change is analysed |

## Shared knowledge

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/projects/{id}/investigations?workflow_filter=` | Investigation history, newest first |
| `GET` | `/projects/{id}/investigations/{investigation_id}` | One investigation |
| `GET` | `/projects/{id}/evidence?subject_id=&field_key=&status=` | Evidence with full provenance |
| `GET` | `/evidence/{evidence_id}` | A single evidence record |
| `GET` | `/projects/{id}/gaps?status=` | Information gaps |
| `PATCH` | `/projects/{id}/gaps/{gap_id}` | Move a gap to `requested` / `resolved` |
| `GET` | `/projects/{id}/assumptions` | Project assumptions and their staleness |
| `GET` | `/projects/{id}/documents` | Ingested documents |
| `POST` | `/projects/{id}/documents` | Upload a PDF (multipart: `file`, `kind`). Validates type, extension and size; returns the document, chunk count and candidate requirements |
| `GET` | `/projects/{id}/documents/{document_id}/chunks` | Page-aware chunks (embeddings stripped from the response) |
| `GET` | `/projects/{id}/requirements?equipment_tag=` | Extracted requirements |
| `PATCH` | `/projects/{id}/requirements/{requirement_id}` | **Confirm or correct.** Sets `confirmed`, records `corrected_from`, and flips the backing evidence to `user_confirmed` |
| `GET` | `/projects/{id}/search?q=&k=` | Hybrid retrieval with page citations |
| `POST` | `/projects/{id}/ask` | Exploratory Mireye question; response carries a disclaimer and is never used in a calculation |
| `GET` | `/mireye/fields` | The cached field catalog |
| `GET` | `/sample-documents` | The synthetic PDFs shipped with the demo |

## Errors

| Status | Shape | When |
| --- | --- | --- |
| `422` | `{error: "validation_error", detail: [...], hint}` | Schema violation (missing location, bad coordinates, negative weight, unknown field, bad upload) |
| `404` | `{detail}` | Unknown project (the message points at `/api/admin/seed`), site, change, evidence, gap or un-analysed impact graph |
| `502` | `{detail}` | Live Mireye call failed in a path that cannot degrade (e.g. explicit geocode) |
| `500` | `{error: "internal_error", detail, request_id}` | Unhandled — correlate with the `x-request-id` header and the JSON log line |

Every response carries `x-request-id`, and every request is logged as one JSON line with method,
path, status and duration.

## Frontend contract

`apps/web/src/lib/api.ts` is the only place the browser talks to the network. It never holds a
credential: Mireye, Supabase, Neo4j and LLM keys exist only in the backend environment. In
development Vite proxies `/api`; in production set `VITE_API_BASE_URL` and `CORS_ORIGINS`.
